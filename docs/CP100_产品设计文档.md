# CP100 产品设计文档

**项目名称：** CP100 像素现实指南针  
**文档版本：** v0.5  
**文档状态：** 产品主线收敛，进入 V0 样机定义和手机端原型阶段  
**更新时间：** 2026-10-24  

> 本文定义 CP100 做什么、给谁用、如何交互，以及第一版产品边界。具体器件、原理图、PCB、供电、天线和采购渠道见 [CP100 硬件设计文档](./CP100_硬件设计文档.md)。

## 1. 产品概述

CP100 是一款 Minecraft 像素风格的实体指南针。

它把手机地图上的目标地点变成手里的实体方向指针：用户可以设置“家”“基地”“宝箱”或任意地点，CP100 通过像素灯持续指向目标；断开手机后，设备使用自身 GNSS 继续完成离线导航。

CP100 的核心体验不是显示大量数字，而是让用户感觉手里拿着一件来自游戏世界、可以在现实中工作的道具。

完整 V1 产品要让用户在 1 分钟内完成：开机、手机连接、校准、选目标、开始导航；手机断开后自动进入 GNSS 导航，到达目标时播放特殊动画。

产品主线是：

> 用户在手机上选一个现实地点，CP100 变成一枚来自 Minecraft 的实体任务指南针，持续把用户带向目标。

## 2. 产品定位

### 2.1 核心定位

> 把地图上的一个地点，变成手里会发光的方向。

### 2.2 产品关键词

- Minecraft 像素风
- 实体游戏道具
- 真实磁北指南针
- 手机选点
- GNSS 离线回家
- 像素灯效
- 可收藏、可把玩
- 低门槛交互

### 2.3 目标用户

- Minecraft 玩家和游戏周边收藏者；
- 喜欢户外、露营、城市探索和寻宝玩法的人；
- 喜欢桌面硬件、灯效和 DIY 电子产品的人；
- 想把手机地图目标变成实体道具的人。

### 2.4 产品原则

- 先给方向，再给数据；
- 用户通过灯效理解状态，不依赖屏幕；
- 手机负责选点和地图，CP100 负责方向和反馈；
- 没有有效定位时不显示伪造的实时方向；
- 趣味性来自任务、主题和到达动画，功能数量服从核心体验。

## 3. 核心用户故事

### 3.1 普通指南针

用户拿起 CP100，设备显示磁北方向。用户旋转设备，像素指针跟随旋转；设备倾斜时，姿态算法进行倾角补偿。

### 3.2 手机设定目标

用户在手机上选择“家”“基地”“宝箱”或任意地图地点。手机保存目标坐标，通过 BLE 把实时目标方位、距离和目标名称发送给 CP100，CP100 显示相对方向。

手机持续提供位置时，由手机计算当前位置到目标的方位和距离；CP100 主要负责测量自身航向并显示结果。

### 3.3 GNSS 离线回家

用户设置目标后，CP100 保存目标坐标。断开手机后，设备使用自身 GNSS 获取当前位置，计算当前位置到目标的方向和距离，继续显示回家方向。

### 3.4 方向锁定

用户按键记录当前方向，CP100 之后始终指向这个方向。这个模式记录的是航向角，适合“沿这个方向前进”；它不等同于地理回家模式，也不能在移动后自动修正为目标地点方向。

### 3.5 到达目标

接近目标范围后，指针颜色、亮度和像素动画发生变化；进入目标半径后播放到达动画。

## 4. 第一版产品范围

### 4.0 V1 首次使用闭环

1. 长按按键 A 开机，像素播放开机动画；
2. 手机端扫描并连接 CP100；
3. 手机提示用户完成转圈校准；
4. 用户选择当前位置或地图地点；
5. CP100 显示目标指针，用户开始移动；
6. BLE 超时后自动尝试 GNSS 离线导航；
7. 进入目标半径后播放到达动画；
8. 用户选择继续导航或清除目标。

## 5. 工作模式

### 5.1 指南针模式

不依赖手机和 GNSS，使用磁力计显示磁北。设备旋转时，指针保持指向磁北。

### 5.2 手机目标模式

手机获取当前位置，用户选择目标地点。手机通过 BLE 发送目标坐标、目标名称、目标颜色和更新后的方向信息。CP100 负责测量自身航向并显示目标相对方向。

手机每隔 2–5 秒发送目标方位、距离和时间戳即可，不要求高频发送。CP100 在手机模式下不需要获得自己的 GNSS 位置。

手机端应把目标坐标作为主数据保存，并把实时 `bearing_true_deg`、`distance_m`、`timestamp` 作为导航数据发送。超过 10 秒没有新数据，CP100 进入手机失联状态。

### 5.3 GNSS 离线模式

手机设置目标后，CP100 保存目标坐标。设备通过 GNSS 获取当前位置，结合磁力计计算目标方向。手机断开后仍可继续工作。

GNSS 搜星时，设备需要明确显示“定位中”；没有有效定位时，不应把旧位置伪装成实时位置。

默认到达半径为 20 m，可在手机端设置为 5–100 m。到达判断需要连续两次有效定位。

### 5.4 方向锁定模式

记录当前固定方位并持续显示。设备移动后仍然指向这个地理方向，不会自动指向某个坐标。

## 5.5 真北和磁北

磁力计测得的是磁北，地图和 GNSS 的目标 bearing 通常是真北。手机模式和 GNSS 模式需要使用磁偏角把真北 bearing 转换为磁北参考；如果 V0 暂时不加入磁偏角模型，手机端必须明确标记为“磁北近似模式”。

## 6. 像素显示设计

现有灯板约为 66.2 mm × 38.7 mm，使用 56 颗 RGB 像素灯。第一版产品保持当前灯板外形和像素布局，硬件细节见硬件设计文档。

### 6.1 指针和颜色

- 红色：当前目标方向；
- 绿色：磁北或已到达目标；
- 蓝色：普通指南针；
- 黄色：校准或定位中；
- 紫色：End 主题；
- 橙红色：Nether 主题。

### 6.2 距离表达

- 远距离：低亮度、冷色；
- 中距离：正常亮度、青色；
- 接近目标：高亮度、绿色；
- 到达范围：快速闪烁或粒子动画。

### 6.2.1 指针映射

- 以设备正面上方为 0°；
- 相对方向映射到 56 颗像素的最近角度；
- 使用 1 个高亮主像素和 2–4 个渐变辅助像素；
- 方向变化使用平滑滤波，避免手持抖动造成跳闪。

### 6.3 状态动画

| 状态 | 动画 |
|---|---|
| 启动 | 像素从中心向外展开 |
| 搜星 | 黄色像素旋转 |
| 定位有效 | 绿色短闪 |
| 磁力计校准 | 环形进度条 |
| BLE 连接 | 蓝色呼吸灯 |
| BLE 断开 | 蓝色慢闪 |
| 充电 | 像素逐格增加 |
| 低电量 | 红色边缘闪烁 |
| 到达 | 绿色粒子爆发 |
| 目标丢失 | 指针变成黄色并缓慢摆动 |

## 7. 交互设计

建议使用两个实体按键，不加入屏幕。

### 按键 A：模式/目标

- 短按：在指南针、当前目标和方向锁定之间切换；
- 长按：启用或清除当前目标；
- 双击：切换最近使用的目标。

### 按键 B：校准/状态

- 短按：显示电量或定位状态；
- 长按：进入磁力计校准；
- 开机时按住：进入固件升级或工程模式。

### 动作交互

- 摇晃和翻转交互放到 V1.1，先验证加速度计误触发率；
- 平放：恢复稳定指南针显示。

## 8. 手机端需求

第一版手机端可以先做成 BLE 配置工具，不必一开始开发完整地图 App。

### 8.1 必须支持

- 扫描和连接 CP100；
- 选择当前位置或输入地图坐标；
- 设置目标名称和颜色；
- 写入目标坐标；
- 设置亮度、主题和更新周期；
- 读取电量、充电、BLE 和 GNSS 状态；
- 清除目标和恢复出厂设置。

手机端是 CP100 的必要组成部分，但 V0 不需要完整地图 App，可以先做无账号的 BLE 配置工具。手机位置权限关闭时必须明确提示；一台手机可以绑定多个 CP100，但一个 CP100 同时只接受一个手机连接。

### 8.2 数据结构建议

目标记录至少包含：

- `target_id`；
- `name`；
- `latitude`；
- `longitude`；
- `radius_m`；
- `color`；
- `enabled`；
- `updated_at`。

实时导航数据包含 `bearing_true_deg`、`distance_m`、`phone_accuracy_m` 和 `timestamp`。手机模式每 2–5 秒发送一包，超过 10 秒无更新时显示数据过期。

手机端把目标坐标作为主数据保存，并每 2–5 秒发送目标真北方位、距离、手机定位精度和时间戳。CP100 保存最后一次有效目标坐标，以便切换到 GNSS 离线模式。

## 9. 产品状态和异常反馈

| 状态 | 用户看到的反馈 |
|---|---|
| 未连接手机、无目标 | 蓝色指南针模式 |
| BLE 已连接 | 蓝色呼吸灯 |
| GNSS 搜星中 | 黄色旋转 |
| GNSS 定位有效 | 绿色短闪后恢复目标指针 |
| 手机数据过期 | 黄色指针慢摆，不显示距离 |
| GNSS 定位精度差 | 降低指针亮度，不触发到达判断 |
| 磁场异常 | 指针抖动并提示重新校准 |
| 目标数据无效 | 黄色指针慢摆，不显示距离 |
| 电量低 | 降低亮度并显示红色边缘 |
| 充电中 | 充电进度动画 |
| 已充满 | 绿色常亮或慢呼吸 |
| 接近目标 | 指针亮度和频率增加 |
| 已到达 | 绿色粒子爆发 |

## 10. 外观和外壳要求

- 保持 Minecraft 像素道具的黑色外观；
- 正面使用半透明或磨砂导光片；
- 56 颗 LED 对应独立像素孔；
- 顶部或侧上方设置 GNSS 射频窗口；
- ESP32 和 GNSS 天线隐藏在外壳内部；
- 外壳优先使用 ABS、PC、PLA 或普通树脂；
- 避免金属外壳、金属喷漆、碳纤维和天线附近金属件；
- 预留 USB-C、两个按键和必要的状态孔；
- USB-C 位于底边中部，两个侧按键分别位于左右直边，按压方向朝外壳两侧；
- 电池不能覆盖 GNSS 天线和 ESP32 天线区域；
- 传感器附近避免钢螺丝、磁铁和铁氧体装饰件。

## 10.1 异常状态处理

| 异常 | 处理方式 |
|---|---|
| 手机未授权定位 | 手机端提示开启权限，CP100 保留指南针模式 |
| BLE 连接失败 | 蓝色慢闪，允许继续使用指南针 |
| 手机数据超过 10 秒 | 进入失联状态，尝试 GNSS 离线模式 |
| GNSS 无有效定位 | 黄色搜星，不显示可信目标箭头 |
| GNSS 精度差 | 指针降低亮度，距离不触发到达判断 |
| 目标数据损坏 | 黄色指针慢摆，要求重新设置目标 |
| 磁场异常 | 停止承诺方向精度，提示重新校准 |
| 电量过低 | 关闭 GNSS，降低亮度，保留 BLE |

## 11. 产品约束

### 11.1 定位和方向精度

- 磁力计受到电源、LED 电流和金属件影响，需要用户校准；
- 室内、楼宇附近和树荫下 GNSS 可能无法稳定定位；
- 手机目标模式的实时性取决于手机位置更新；
- 低速或静止时不能使用 GNSS 航迹方向代替磁力计航向；
- 地图 bearing 通常是真北，必须使用磁偏角转换到磁北参考；
- 方向锁定模式只保存方向，不等同于回家导航；
- 目标指针是“方向提示”，不替代专业户外导航设备。

### 11.2 功耗

- 56 颗 LED 不长期全白满亮；
- 默认降低亮度，避免灯效耗尽电池；
- GNSS 可以按目标模式动态降低更新频率；
- BLE 配置优先于 Wi-Fi，减少待机功耗；
- 低电量时优先关闭 GNSS 和降低 LED 亮度；
- 1000 mAh 电池在普通目标动画下以约 2–3 小时为首版目标，1500 mAh 以约 3–4.5 小时为目标，最终以样机实测为准。

### 11.3 尺寸

- 首版沿用现有约 66.2 mm × 38.7 mm 灯板；
- 产品外壳围绕灯板、USB-C、按键、电池和双天线布局设计；
- 后续增加陀螺仪、扬声器或振动马达需要重新评估空间和电池容量。

## 13. 产品验收标准

### 13.1 V0/V1 可验收指标

| 指标 | 目标 |
|---|---|
| 首次连接 | 用户 60 秒内完成 BLE 连接 |
| 校准 | 60 秒内完成，并有绿色确认反馈 |
| 磁北显示 | 校准后静止方向误差目标 ±5°，以实际场地测试为准 |
| 手机数据更新 | 2–5 秒一包，超过 10 秒进入失联 |
| 指针响应 | 手机目标变化后 2 秒内更新显示 |
| 到达触发 | 默认 20 m，连续两次有效定位才触发 |
| GNSS 状态 | 无有效 fix 时不显示确定目标箭头 |
| 充电运行 | 充电时不反复重启，高亮时允许降低充电速度 |
| 低电量 | 先降亮度，再关 GNSS，最后保留 BLE |

V1 样机需要通过以下验收：

1. 平放和轻微倾斜时能够稳定显示磁北；
2. 用户完成校准后，普通指南针方向无明显跳动；
3. 手机能设置目标并断开 BLE 后保留目标；
4. GNSS 获得有效定位后，设备能显示目标相对方向；
5. 进入目标半径后播放到达动画；
6. 充电时设备可以继续运行，不出现反复重启；
7. 低电量时亮度和 GNSS 行为符合预期；
8. 两个按键的短按、长按和双击逻辑稳定；
9. 外壳安装后，ESP32 BLE 距离和 GNSS 搜星能力满足目标；
10. LED、磁力计、GNSS 和充电模块同时工作时系统不异常发热。
